# Model gateway and screening protocol fixture

`createGatewayFixture` provides a normally trusted HTTPS destination for the native model gateway signer and security-screen client. It uses only synthetic credentials and a fixed loopback or explicitly named fixture-internal model upstream. It has no AWS credential discovery, STS call, external forwarding, or production key. Its receipts are always unqualified.

Gateway requests require the configured API key, exact host/method/path, fresh SigV4 date, fixed region/service/credentials, and an independently recomputed body signature using the installed AWS SDK. Unknown models, unsigned payloads, changed bodies and malformed signatures fail closed. Model listing and metadata support native catalog discovery. Message forwarding translates the configured model alias and streams the companion response with backpressure; signing credentials are never forwarded.

The pinned AWS proxy copies incoming headers after signing, so the API key is authenticated separately over TLS; the verifier requires signed host/date/session-token headers and verifies every header actually named in `SignedHeaders`. This follows the observed native binary and the [upstream proxy implementation](https://github.com/awslabs/aws-sigv4-proxy/blob/master/handler/proxy_client.go), rather than requiring an additional signature on headers the proxy does not sign.

Security requests require their own synthetic token, native hook/chunk coordinates and an explicitly admitted synthetic text digest. Known allow/block digests return controlled classifier scores; all other text rejects. Delay is an explicit fixture input. Receipts retain byte hashes, coordinates, outcomes, completion/abort state and elapsed time, never request text or credential values. Disconnects cancel screening delays; cancelled responses cannot count as completed screenings. A throwing receipt sink is fatal: the owning supervisor must mark that process failed and clean up its owned services. Missing receipts are never successful evidence.

Each terminal receipt includes absolute start/end times and bytes passed to the response stream, including partial failures. These are bytes emitted at this hop, not acknowledgement by the caller; failed output cannot count as completed model work. The upstream deadline defaults to 120 seconds. An explicit integer `upstreamTimeoutMs` between 1 and 900,000 milliseconds supports bounded longer synthetic waits. A campaign must derive it from its exact model delays, chunk spacing and transport margin before activation; the helper does not infer that calibration.

The focused test runs actual TLS requests through the native catalog and screening clients, including chunk coverage and rejection cases. A separate operator-owned isolated Docker proof is required for the pinned signer binary itself; no core overlay is performed by this helper. Keep its image/config/source hashes, native receipts, resource limits and exact owned cleanup with the campaign evidence.

This fixture does not reproduce external inference, STS, API Gateway or classifier capacity. Those waits and limits still require measured calibration or explicit finite sensitivity bounds. Native Pi runs, screening audit outcomes and two-core ownership must also be proven by the campaign; a passing protocol test alone cannot qualify performance.

A prepared child workload may additionally bind `security.nativeFragments` with an exact provider name, native tree run cap (2–10), and a finite list of chunk templates. Each template binds `id`, `hook`, `chunkIndex`, `chunkCount`, a `surface` literal, and a `text` literal. A tool-response template also binds `request.textSha256` and the native `request.truncated` bit. Both literals have the form `{text, fields}`; every field specifies `{name, offset, from, length}` in UTF-16 code units. The only field names are `childSessionId`, `parentSessionId`, `childRunId`, `mailAt`, and `remainingSlots`. Their grammars are lowercase native UUIDv4, canonical millisecond UTC timestamp, and one native remaining-slot digit bounded by the declared cap. A partial span preserves its position within that fixed-width field. All other characters must match literally; profiles cannot supply regular expressions or wildcard captures.

These templates must come from the actual native task, result, and mail renderers, with the exact bound parent/child tasks, output, caller title, source, and request context. Native task prose is not universally XML-escaped. Whether an inbound child is labeled `session-delegation` depends on the native sender-participant check; an automated parent without that participant instead retains its native surface label. Do not infer either format from a marker alone. Compile both native chunk layers (7,500/500 and 1,600/256 overlap) and preserve any field fragments across cuts. The dynamic path also requires canonical JSON, exact metadata keys, matching provider/qm coordinates, automation origin, native request UUID, and exactly one matching template. Existing static allow/block hashes retain their behavior.

A native-fragment receipt adds only the matched rule ID, text digest, bounded typed field fragments, and `reconstructionRequired: true`. Admission establishes a declared synthetic fragment, not ownership of a child or completion of the whole screening. Final evidence must contain every coordinate exactly once, reconstruct the original native payload and raw body hashes with consistent overlaps, and bind each complete UUID/timestamp/slot to the actual owned parent tool call, child run/session, eligible terminal result, and canonical mail. Missing, duplicate, contradictory or foreign fields must fail final verification. Native screening submits two chunks at a time, so the gateway answers each validated fragment without waiting for later chunks. Whole-attempt reconstruction and ownership remain required campaign evidence, alongside all model/tool counts and runtime closure.
