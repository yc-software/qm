# Clone-in-the-Loop

I'd like to extend QM with a Clone that uses GBrain to retrieve my past instructions and feedback, along with any history my team chooses to share. The [Clone SDK](https://github.com/cloneisyou/clone-sdk) would use that context to suggest what I'd ask an agent to do next. The application would then use QM to execute the instruction, review the result, and request changes. I could press Tab to accept a suggestion, press Tab again to let the cycle continue, and press Stop to take control back.

The idea is to make the judgment in past conversations useful in the next piece of work. Clone SDK would provide next-prompt prediction and draft completion, QM would handle execution and structured review turns, and GBrain would supply source-scoped context. The SDK would not execute agents or start the loop; Tab acceptance and the second-Tab shortcut would remain application behavior. I'd also like to explore a team workspace where a teammate's Clone could draw on shared feedback to help with recurring research, product, and marketing work.

I've built [a hackathon prototype](https://github.com/cloneismin/clone-in-the-loop) to try this out, with a [demo](https://www.loom.com/share/f989c778d4f14d05acfe0a20d9bdfbc3) and [instructions for running it locally](https://github.com/cloneismin/clone-in-the-loop#quickstart). The runnable prototype is on the fork's `main` branch; this PR contains only the proposal. Hosted predictions require a server-side app key and send selected Goal, conversation and GBrain excerpts to Clone. The linked demo predates this SDK revision. The prototype runs as a local web app for one trusted operator and uses clearly labeled fictional teammate history. I'd love to hear whether this would be useful in QM and where it might fit.
