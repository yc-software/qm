# Sandbox recovery

The agent runs in core. Sandbox home state is working state with a provider-specific recovery window. Publish code to git and deliverables to Files when they must remain durable and accessible independently of compute.

Modal uses native directory checkpoints of `/root`, mounted into a fresh sandbox when the current sandbox is replaced. It does not stream the home through core during routine checkpointing or rollover. The base image supplies system dependencies outside the home; a home checkpoint does not preserve processes, RAM, or system-wide package installs. Runtime credential files under `/tmp` are outside the directory checkpoint; ordinary home files and symlinks are included.

`MODAL_NATIVE_SNAPSHOT_INTERVAL_SEC` defaults to 300 and controls checkpoint throttling independently of the legacy `MODAL_SNAPSHOT_INTERVAL_SEC`. Used-turn teardown, replacement, and idle reaping capture checkpoints. The existing deep-idle maintenance sweep also checkpoints active machines when due, including machines running background work. This is best-effort recovery, not a guarantee that a process running into the provider deadline has saved its latest writes. Background maintenance must be enabled; the sweep cadence depends on the configured idle intervals. Captures while processes write are not application-consistent database backups.

`MODAL_SNAPSHOT_RETENTION_SEC` defaults to 2592000 (30 days) and must be positive. Checkpoint IDs, capture timestamps, errors and expiration times are stored with sandbox records. `ARTIFACT_STORE` must be durable to retain these references across core restarts. Status reports `recovery.checkpointExpiresAtMs`; using a checkpoint does not renew its expiry. Expired or failed native restores stop with an explicit recovery error instead of replacing the home with an empty directory or silently using an older portable backup. Idle machines whose checkpoints expire are not automatically renewed.

E2B creates persistent machines with an explicit pause-on-timeout lifecycle and pauses them at teardown. Routine native pause does not create a second tar backup. Provider pause retains disk and normally memory; provider fallback may retain disk only, so reconnectable processes must not depend on RAM surviving. Status can inspect a paused machine without waking it. Pause failures are recorded and returned, with the running machine retained for retry. A lost native machine requires explicit recovery rather than an automatic blank replacement. Existing E2B machines whose lifecycle does not confirm pause-on-timeout retain legacy portable checkpointing.

Explicit home export/import and `persistHomeSnapshot` continue to use the portable tar format for cross-provider moves and chosen recovery. Configure `MODAL_SNAPSHOT_S3_BUCKET` or `E2B_SNAPSHOT_S3_BUCKET` to retain those portable copies durably. They are not silently selected instead of a failed newer provider checkpoint.
