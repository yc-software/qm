Compile on a Mac with `clang -fobjc-arc -framework ApplicationServices -framework CoreGraphics -framework Foundation tests/manual/focus-trace.m -o /tmp/desk-focus-trace` from `desktop/desk`.

Run `/tmp/desk-focus-trace 2> /tmp/desk-focus-trace.log`, then run `python3 tests/manual/background-input.py --desk target/release/desk --app com.google.Chrome --x FIELD_X --y FIELD_Y` against an empty disposable field while it observes for 20 seconds. The trace logs only monotonic time, source and target process IDs, notification subtype, focus subject PID, theft ID, live AX foreground PID, and the first eight window IDs before/after. It does not inspect or suppress keyboard text. Check whether foreground PID and window order remain stable, and whether type-21 notifications appear around synthetic input. This is a diagnostic, not proof of prevention; do not post its log publicly without reviewing it.

For the lease protocol, correlate `0x4000` (taken), `0xf102` (changed, carrying the theft ID), and `0x8000` (returned). A `0x2` notification is a new-front transition, not the same as a temporary key-focus lease. Record the macOS version and candidate commit. The trace is diagnostic instrumentation and can affect timing; repeat acceptance checks without it.
