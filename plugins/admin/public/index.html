Ambient policy

What the agent proactively acts on in this channel. The standing order is plain prose the ambient judge weighs each batch of new messages against — empty means it stays silent unless addressed. The bot ledger says how each automated poster is treated: ignore never wakes the judge, rollup batches its posts (judged at most once per the given hours), action marks its posts as triggers to act on, user reads it like a person.

When off, the agent never wakes on overheard messages in this channel — it only responds to direct @mentions. Default: on for channels with 8 or fewer members, off for larger ones.

External Slack participants

Org-wide, default off. When on, internal members may chat with the agent in Slack rooms whose audience includes an external user (Connect member or guest) — its replies, and anything it reads there, are visible to those externals. Externals themselves still can't interact.

Ambient behavior

Org-wide, default on. When off, the agent never acts on overheard messages in any channel, regardless of per-channel settings — it only responds to direct @mentions.

Channel pinned header

Org-wide, default off. When on, the agent posts and pins a small header message (naming the model in use) in every Slack channel it's in. Channels can still override it either way from their project page.

Models & browsing

The models, browser runtime, and organization context available on future turns.

Fast mode for interactive turns

Org-wide, default off. When on, human turns run in fast mode on fast-capable models unless the turn asks otherwise. Requires fast-mode quota with the provider.

Individual authorization for AI usage

Org-wide, default off. When on, each user must connect their own Claude or Codex account (API key or subscription login) before using the assistant. The org's shared model credentials are not used for their turns.

Default harness and model

The runtime inherited by scopes without an override. Takes effect from the next turn.

Approved harnesses

Harnesses people may choose in the web UI or ask the agent to use.

Allowed models

Restrict which models the web UI offers and accepts, org-wide. Add the models to allow and pick which is pre-selected by default. Remove every chip to allow the deployment's full model set.

Branding

How this org's surfaces look. Accent is the highlight color across the web UI, admin, and portal; mark is the 1–2 character badge in the web UI; label is the assistant's name everywhere it introduces itself; organization name is how the assistant refers to this org. Leave a field blank to use the deployment default.

People directory

Public page or URL where the agent can look up a person's current role or title (e.g. https://www.example.com/people). Used when getting to know someone. Leave blank to disable.

Slack ack emoji

The emoji the bot may react with to acknowledge a Slack message, org-wide. Add names from the workspace's emoji (custom and standard). Remove every chip to restore the built-in rotation.

Browse model

The model driving the browser agent in the browse skill, org-wide. Leave on the default to follow the deployment's base model. Fast mode applies only on Opus models; other models run at standard speed.

Browse step limit

Max browser steps a single browse task may take, org-wide. Each step is one action (click, type, navigate) by the browser agent. Leave blank for the default of 50.

Turn time limit

Maximum wall-clock time for a turn, org-wide. Use 60–86400 seconds, 0 for no limit, or leave blank to use the deployment default.
